# cykl-lifecycle v3.0-R2 — minimal v3.0.1

2026-10-17 · replaces the proposed v3.0 design · stdlib Python, offline implementation.
MUST denotes a mechanically checked contract unless explicitly marked human responsibility.

## 1. Authority and scope

GitHub issues own assignment, scope, acceptance and status; milestones describe releases.
GitHub Releases own published changes and rollback notes. Local packets are observations,
not a second queue. NOW owns current continuity; DECISIONS owns decisions and lessons.
Only `lifecycle.py` writes lifecycle state. Keep the seven `cykl-*` names; English aliases
are descriptive text only. Offline work continues ONLY an already-dispatched packet in
one shared worktree. New dispatch, scope changes, acceptance and publication await online
reconciliation. v3.0.1 provides local persistence/validation, not a GitHub API client.

## 2. One budget and bounded readers

All sizes are exact UTF-8 bytes including metadata and newlines. Every helper response
is buffered and limited to 16,384 bytes; failure prints no partial state. Diagnostics
are at most 1,024 bytes. There is no runtime token counter or token fallback. The old
5,000-token figure is a design intent, not a second guarantee or a CI pass claim.
Harness/system/user/tool-schema overhead is outside the helper budget. `context` includes
the current packaged skill, all seven descriptions, present root AGENTS/CLAUDE files,
config, NOW, roadmap, applicable decision rows and requested bounded files in its budget.
Nested skill calls reuse this projection, not accumulate repeated startup payloads.
Arbitrary agent tool reads cannot be sandboxed by this package; the enforcement boundary
is helper output, packaged instructions and required repository checks.

| Surface | Cap (bytes) |
|---|---:|
| NOW | 4,096 |
| PROJECT_CONFIG | 2,048 |
| ROADMAP projection | 4,096 |
| Legacy HANDOFF / LESSONS_CANON pointer | 512 each |
| Root or nested AGENTS.md / CLAUDE.md; packaged SKILL.md; template/reference | 4,096 each |
| Skill description | 512 |
| Decision index row | 2,048 |
| Packet; decision body; local issue body (including pinned body) | 8,192 each |
| Attempt / outbox operation / sync status | 2,048 each |
| Result | 2,048 and 15 lines |
| Archive chunk | 65,536, UTF-8 line boundaries |
| Additional explicitly requested file | 8,192 |

DECISIONS and migration manifests are streamed stores: no total history cap, no raw
skill reads. Their emitted projections share the 16,384-byte cap. Large source lines
that cannot fit an archive chunk block migration; no byte splitting or truncation.
Skill/template lint rejects raw history reads and raw issue-view commands. Unknown
files under owned queue/sync/issues paths fail; product code and fixtures are outside
lifecycle shape/marker checks. Every additional skill read goes through `context --file`.

## 3. Files and canonical format

`docs/NOW.md` is Markdown wrapping one indented JSON object (UTF-8, LF, final newline).
Keys: schema=3, checkpoint (UUID), previous_sha256, content_sha256, parents (checkpoint
UUIDs), base (checkpoint UUID or null), goal, position, next, preserve (at most ten
strings), work (O-* obligations and A-* attempts mapped to exact text), risks,
references (D-* decisions / L-* lessons), reconciliation. Repo and branch are explicit
identity strings. Hash the exact Markdown bytes with the content_sha256 line removed.
Readers reject duplicate keys, wrong types, unexpected keys and hash mismatch.
Preserve overflow must become named O-* work entries in the successful checkpoint;
the script performs that conversion, then checks the resulting NOW cap.

`docs/DECISIONS.md` starts `# DECISIONS`, then a TSV header:
`id kind status scope supersedes text` (actual tabs). Text is a JSON string, preserving
Unicode, whitespace, CRLF and missing trailing newline from extracted facts. Kinds:
decision/lesson. Status: proposed/accepted/retired/superseded. Scope: project,
archived, or task:<id>. IDs and supersedes links are unique, resolvable and acyclic.
No textual inference of rule conflict: a human records a superseding disposition.
Startup selects accepted project rows plus explicit NOW references; task selection
also includes its accepted rows. Histories may grow without growing the startup.

Optional local files: `docs/queue/T-*.json` packets, `docs/queue/attempts/A-*.json`,
`docs/queue/results/*.md`, `docs/sync/status.json`, `docs/sync/outbox/*.json`,
`docs/issues/*.md`. Packet includes attempt, issue_url, revision, base, allowed_paths,
excluded_paths, acceptance, offline=true and task_budget_bytes (1..65,536).
Default exclusions include historical storage and unlisted decision bodies. Attempts
must have packets excluding `docs/archive/` and `docs/DECISIONS.md`. Context normalizes
requested paths, denies raw history/index reads, applies active packet exclusions and
allows decision bodies only for IDs listed in NOW references. Attempts
record status (running/paused/result-ready/integrated/abandoned) and packet path.
Terminal attempts may leave NOW only with an explicit closure; their bounded packet/attempt
files remain as evidence and are excluded from startup. NOW stores live attempt IDs, not mutable status. Context projects current attempt records.
Context derives pending count and oldest ID (lexical operation-ID order) from the outbox,
then projects bounded sync status; it never prints an ever-growing pending list.
A conflict is recorded locally as an O-* obligation; it does not stop unrelated work.
There is no network reader/writer or executor file-slicing service in this release.

## 4. CLI and sole writer

Shared executable: `skills/cykl-start/scripts/lifecycle.py`, Python 3.9+ standard library.
It never invokes git or the network. Paths are relative, repository-contained, and
symlink-free on managed surfaces. Commands:

- `check --root ROOT`: read-only size, shape, identity, references and packet checks.
- `check --merge-result --root RESULT --parent LEFT --parent RIGHT --base BASE`:
  synthetic merge-result gate. Without `--merge-result`, also check explicit checkpoint
  parent/base UUID declarations against these source snapshots.
- `check --trusted-root TRUSTED`: additionally require the result workflow SHA-256 to
  match the trusted tree; available with both project and package checks.
- `check --reconcile-template --root RESULT --parent LEFT --parent RIGHT --base BASE`:
  emit a bounded closure draft for missing IDs; restore each ID or review its closure reason.
- `check --package`: lint bundled skills/templates; usable in this package repository.
- `context --root ROOT --skill cykl-start [--task ID] [--file PATH]`: validated projection.
- `checkpoint --root ROOT --input DRAFT.json --expected HASH`: validate then replace NOW.
  Draft has repo, branch, goal, position, next, preserve, work, risks, references;
  optional parents/base/reconciliation, decisions (whole index text), files (bounded
  managed path -> text). `--expected absent` initializes only an empty lifecycle root.
- `decisions --root ROOT`: stream/lint index, emit a count only.
- `decisions add --root ROOT --input ROW.json --expected HASH`: append one row under
  the writer lock, retain existing index bytes, mint NOW and return its card plus new line.
- `migrate --root ROOT [--output NEW_PLAN.json]`: inventory to a new file outside ROOT
  (unique temporary file by default); stdout contains only path, SHA-256 and source count.
- `migrate --root ROOT --plan PLAN.json`: read-only validation of the reviewed plan.
- `migrate --root ROOT --plan PLAN.json --apply`: explicit application of reviewed plan.
- `migrate --root ROOT --rollback --dest NEW_DIR`: verify and reconstruct original
  migration sources into a new, separate directory; never replace live state.
- `archive show --root ROOT --source PATH --lines A-B`: bounded line-addressable retrieval.
- `recover --root ROOT`: verify saved stage and original/target hashes, finish interrupted
  promotion; refuse concurrent live writers or unrelated changes.

Writer acquires `.cykl/lock` with O_CREAT|O_EXCL. Never silently steal locks. Recovery additionally acquires `.cykl/recover.lock` with
O_CREAT|O_EXCL, so recovery processes cannot race each other. A staged
candidate is fully validated before promotion. A single local recovery descriptor
records original/target hashes, not transaction pages or an event history. Files are
fsynced and atomically replaced under the lock; readers refuse the lock, including a
stale lock after a partial multi-file promotion. Recovery is explicit and hash checked.
NOW is promoted last; acknowledgements appear only after rereading the promoted state.

`checkpoint` returns a bounded compaction card with repository, branch, NOW path,
checkpoint UUID/hash, Preserve, work IDs and reload command. It first validates the
card's size, then writes. A skill may say “saved” only after that acknowledgement.
Failed writes halt dependent close/compaction actions. Unexpected harness compaction
cannot be intercepted universally; only acknowledged facts have this guarantee.
Unwritten thoughts remain unrecoverable. No chat summary overrides disk.

## 5. Parent-union merge invariant (blocker fix)

The caller supplies the actual result tree, BOTH actual parents, and their merge-base.
CI derives ancestry from the tested merge commit, never from PR-provided paths. Exactly
two parents are supported; octopus or missing ancestry fails. Schema removal/downgrade
fails even when the result deletes its configuration. A legacy parent can be inventoried
without parsing it as v3, but cannot justify losing an existing v3 parent's state.

For every O/A/D/L ID present in NOW work or DECISIONS in either parent OR base, the result
MUST retain that ID in work/DECISIONS or explicitly close it in merged NOW. A closing line
is a reconciliation entry keyed by ID, with action `close` or `supersede` and a nonblank,
reviewed reason. Supersede also requires a retained successor; a closed ID cannot remain
active. A `keep` or `update` row cannot excuse a missing ID.

This check compares only ID presence and explicit closure. It does not compare record
text, metadata, ordering, timestamps, settled rows or historical source hashes. Parent/base
reconciliation rows do not add obligations to the union. Existing `sources` lists remain
readable but are not compared; new reconciliation templates and closures need no hashes.
Local checkpoints likewise require a closing line for removed IDs and preserve prior
closure IDs, without comparing their text or hashes.
For separately authored checkpoints, strict ancestry checks require NOW to name both
source checkpoint IDs and the base checkpoint. Synthetic merge checks instead obtain
ancestry from the caller and do not require a writer to run on GitHub's synthetic commit.
Unchanged NOW, one-sided changes, and changes on both sides pass when the union of IDs
is retained or explicitly closed. A second PR after a settled update passes with unchanged
NOW or metadata-only changes. Selecting one valid NOW while silently dropping the other
parent's or merge-base's obligations fails.
V3 archive files and extraction manifests from any parent/base are immutable in the result.
A legacy archive may be replaced only when a verified migration manifest reconstructs
that parent archive with the exact original hash.
This proves explicit accounting, not the truth of a human's closure explanation.

## 6. Migration (blocker fix)

Default inventory makes no project writes; its plan file is external and its stdout is
bounded independently of inventory size. Reviewed-plan dry-run writes nothing.
As corrected in 3.0.1, inventory selects only CONFIG, HANDOFF, ROADMAP and LESSONS_CANON.
CONFIG retains static sections; only Current Sprint is replaced by default. All other
files are kept unless explicitly opted in with `extra_sources` or `replacements` and
reviewed source metadata. Instructions always require replacements. Generated writes
cannot overwrite unselected files. See [v2 provenance](../migration-scope-v301.md).
Plans include keep lists; stdout shows bounded change/keep previews. No “newest Snapshot” heuristic.
Each source has bytes, line count and SHA-256; UTF-8 must decode strictly. A plan assigns
EVERY line exactly once to active or archived, with reviewer reason. Initial unresolved
ranges and unresolved checklist entries block apply. Active ranges carry a unique O/A/D/L
ID; O/A text goes into NOW, D/L into DECISIONS. Decision/lesson scope defaults archived;
promotion to project is explicit. Exact decoded extracted text MUST reconstruct the
source bytes together with the archived remainder. Only the remainder is stored as
plain grep-able UTF-8 chunks, with original path, line ranges and SHA-256 in a manifest.
The manifest retains exact extracted facts as provenance, not a second live state store.
`archive show` reconstructs requested original lines from this verified evidence.

Reviewed checklist: active-fact classification, snapshot ambiguity resolved, issue URL
mapping reviewed (attach-only; no title matching), all readers converted, all writers
converted, privacy reviewed. Each check has a nonempty evidence string. Each source range
has a review reason. Mechanical coverage cannot discover a fact wrongly marked historical;
that semantic judgement belongs to the reviewer. Sources are rehashed under the lock.
Known secret patterns are scanned locally; each hit requires an acknowledgement ID tied
to the source hash/line. No automatic redaction. A scan cannot prove publication safety.
Owner review is required before putting any private archive in a public repository.

Replacements for old entry points must be explicit and bounded; unrelated instruction
content cannot disappear without appearing in the extraction/remainder manifest. CONFIG
becomes schema 3, legacy state files become pointers, NOW/index contain active facts.
The saved manifest records verified checklist/source evidence. Apply is idempotent for
the same plan hash; changed plans/inputs cannot silently reuse an earlier migration.
An old `porzadek.py` installation is unsafe: upgrade all writers. The shipped compatibility
file refuses every invocation (exit 2, no writes) and directs users to lifecycle.py.
Rollback reconstructs originals into a separate recovery directory; do not overwrite live
v3 state or remove merge checks. Archive searches remain possible with ordinary grep
outside agent startup, or the bounded archive command inside a skill.

## 7. Privacy, GitHub and protection

Mirroring is disabled by default and no publishing command ships in v3.0.1. Future
mirror automation must opt in, even for private repositories. Only manually reviewed
public-safe Identity/Goal/Position/Next and IDs may be selected. Preserve, Risks and
decision bodies are excluded. The prepared pin and every work-issue body are capped
at 8,192 bytes by `check`; long acceptance material belongs in a named repository path.
Do not copy inventory/research notes or private project data into this public package.
Regression fixtures are generated synthetic bytes, not recovered project documents.

Sample pre-commit validates the full staged tree; hooks can be bypassed. Required check
`lifecycle-integrity` validates PR test merge and merge-group result against both parents
and merge-base, with no path filters. Protected-branch pushes only detect regression.
Use a trusted target/released validator, not candidate Python. Compare candidate workflow
bytes with the trusted version before project/package validation. This check can itself
be deleted from editable YAML: each adopter MUST independently enforce a required workflow
from a protected definition/ref, or require CODEOWNERS approval on workflows, CODEOWNERS
and the validator with stale approvals dismissed and ordinary bypass disabled. Protect
the trusted-ref setting. Require up-to-date branches or merge queue. Each repository MUST configure
this check in its ruleset, forbid ordinary bypass/direct pushes, and run a canary PR
restoring HANDOFF >512 bytes that a non-admin cannot merge. Record ruleset/canary evidence
in PROJECT_CONFIG. Until verified, keep `merge protection unverified`; this package cannot
configure or certify external repository protection offline. Admin bypass is out of scope.

## 8. Cuts, acceptance and implementation boundary

Removed: event log, paged transaction files, runtime tokenizer, per-obligation continuity
JSON, permanent release export. Git plus NOW hashes provide history. No second queue,
network service, automatic import/dispatch/release publication, or broad cleanup.

unittest must cover: two valid parents losing obligations; one-sided changes; both-sided
changes with the union retained; closures with reasons; base-only IDs; a second PR after
a settled update; metadata-only changes; extracted active facts vs archived remainder; unresolved/
gapped plans; source drift; exact CRLF/Unicode reconstruction; cap boundaries; synthetic
420,976-byte HANDOFF resurrection; stale expected hash; locks/recovery; bounded context;
decision cycles; privacy scan acknowledgement; no-write v2 compatibility. Build both plugin
and skills archives and verify parity. Server protection and token measurements remain
explicitly unverified in this offline implementation.
