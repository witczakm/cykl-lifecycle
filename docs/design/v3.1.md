# cykl-lifecycle 3.1.0 — delta to R2

Additive minor release. NOW schema stays 3; no new subcommand; no migration.

## 1. Task authority by `TASKS`

`PROJECT_CONFIG.md` may carry `TASKS=github` or `TASKS=local`. A missing line means
`github` (3.0.x behaviour); any other value fails `check`. Mirroring and the GitHub-only
trusted-workflow hash comparison are unchanged.

With `TASKS=local`, `docs/ROADMAP.md` is the task index and `check` validates it:
- task lines are `- T-<id> <open|doing|done|dropped> <title>`; IDs are unique;
- every `open` or `doing` task has `docs/issues/T-<id>.md` (8,192-byte cap);
- a packet's `issue_url` is an existing `docs/issues/T-<id>.md` path.

## 2. Lead surfaces (optional skill `cykl-prowadzacy`)

| Surface | Cap | Handling |
|---|---|---|
| `docs/lead/THREADS.md` | 2,048 B | managed, written only through checkpoint `files`, projected by `context` |
| `docs/lead/LEAD.md` | 4,096 B | managed, Owner-edited config, read with `context --file` |
| `docs/lead/JOURNAL.md` | none | unmanaged, append only, never loaded; grep by ID |

When `docs/lead/LEAD.md` exists, `check` additionally requires: a packet with `model` also
has a non-empty `model_reason`; every `docs/queue/results/*.md` starts with
`=== SHORT ===` and has at most 8 further lines. Without LEAD.md these checks do not run.

## 3. Package

The package holds the seven core skills and at most `cykl-prowadzacy`; any other skill
name fails `check --package`. `install.sh --edition core|multi` installs 7 or 8 skills and
replaces all existing `cykl-*` folders so versions never mix.

## 4. Compatibility

A 3.1.0 project passes a 3.0.x trusted validator: that validator ignores `TASKS=` and
does not scan `docs/lead/`. Mixed skill installs are not supported.
